Supercharged Bitcoin payment experiences

Scan a QR code and the merchant's order page opens inside your wallet, drawn with the wallet's own buttons, lists and forms. Pick what you want, then pay on the wallet's own payment screen. The merchant needs no website, and the wallet needs no browser. Simple to implement by any wallet.

How it works

  1. 01

    Scan

    The QR code is a cop:// URI: the server's iroh key, optionally a relay, and whatever parameters the merchant wants to pass, like a table number or a POS terminal.

  2. 02

    Connect

    The wallet dials the server and sends those parameters along with a random session string it just generated, so it can find this order again later.

  3. 03

    Order

    The server sends the page as hypereffect elements and signals, and the wallet draws them natively. Taps go back as action messages, and the server can update the page as necessary.

  4. 04

    Pay

    At any moment (commonly after the user has made their choice and clicked to pay) the server sends an invoice and the wallet shows its native payment screen.

What it's for

Commerce, inside the wallet

Anything a merchant can describe with text, buttons, lists and form fields can be an order page. A few of the use cases:

Menus and carts

Browse what's on offer, pick options and quantities. The server keeps the running total and sends one invoice for the lot.

Open amounts

Tips, donations, top-ups: the customer types or picks the amount, and the invoice is generated for exactly that.

Restaurant tables

One QR code per table, each carrying its own parameters. The server can take orders directly and later collect the payment.

Refunds and cashback

The server offers money with an invoice request. If the customer accepts, the wallet issues an invoice with its own keys and the server pays it.

Unattended machines and offline experiences

A vending machine or kiosk displays a QR code while the server runs elsewhere.

Coming back to an order

The wallet remembers each session's string and parameters. Reconnect with them for a receipt, a delivery update, a refund, or another month of a membership.

No browser in the wallet. No website for the merchant.

The wallet draws every order page with its own native components, so it looks and behaves like the rest of the wallet. The merchant needs no web server, no domain name and no certificate: an iroh key is the address, and it works from anywhere.

The server is the merchant

A shop, a restaurant, a vending machine, running on an always-on machine or the merchant's own phone. It describes the page, reacts to what the customer does, and sends invoices.

The client is the wallet

It draws the page with its own UI toolkit. The page is hypereffect: text, buttons, text fields, lists, rows, images and a few more, small enough for any wallet to support.

The connection is iroh

The QR code holds the server's iroh key. The wallet dials it (cassis-order ALPN) and both sides exchange messages. Custom relays and Tor are supported

The payment screen is the wallet's

The server can draw whatever page it likes, but not the payment screen. What you pay, and to whom, comes from the invoice, and your wallet shows it.

Interactive examples

Scan a code

The phone is the wallet, and its camera is pointed at a café terrace. Drag the picture until a QR code sits in the frame, then tap through what opens. Some codes open a whole order; one is a single invoice with no page at all.

  1. 01 The laptop An online shop's checkout. An invoice for the cart comes straight back, with no page at all.
  2. 02 The tip sign The street musician's tip jar: a form with an amount, a name and a request. The invoice is for whatever you typed.
  3. 03 Table 21 The café's menu. Order straight to your table and pay in sats for prices set in dollars.
  4. 04 The gym card Your membership. Pay for next month, or cancel and get the unused days back.
